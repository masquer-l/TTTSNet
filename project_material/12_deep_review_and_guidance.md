# 12 项目深度复盘与指导文档

**创建时间**: 2026-07-18
**复盘范围**: 基金申请书（正式版）× TTTSNet 仓库代码/实验 × 前期 TTTS_SAM / UDP_PERSAM 证据链
**目的**: 把"基金愿景"和"当前真实资产"对齐，指出差距、口径问题和落地风险，并给出论文（短期）与基金（三年）两条线的收敛路径。

## 0. 一页纸结论（先看这里）

1. **你有两套并行的东西，但它们没有对齐**：
   - 一套是**基金申请书**里描述的宏大三年愿景（拓扑感知分割 → 骨架/图谱 → 短窗口配准 → 交通支候选 → 专家确认）。
   - 一套是**实际能跑、有数据的代码资产**（TTTSNet 单帧分割 + ViT backbone + 一堆负结果）。
   - 当前代码只覆盖了愿景的**第一环（单帧分割）**，且用的是和申请书主打的"SAM 提示驱动范式"**不同的技术路线**（TTTSNet 是 custom CNN，ViT 只是被塞进去当 backbone）。

2. **当前最强、最稳、可写论文的资产是**：`TTTSNet-v2.1.0`（ViT backbone + 分层学习率）
   - 内部 Val：mIoU **0.6389 ± 0.0025**，Dice 0.7652，clDice 0.837
   - SFY 跨域：mIoU **0.6524 ± 0.0080**，Dice 0.7723，clDice 0.837，surface_dice@5px 0.652
   - 这是三个 seed 的稳定结果，是唯一可以当"锚点"的东西。

3. **一堆方向已被证明当前无效**（都是诚实的负结果，别再反复投入）：时序一致性 loss（v1/v2/v3 均 ≤ baseline）、半监督 v2、Transformer decoder、AUFL loss。clDice 只有微弱正收益（0.6389→0.6417）。

4. **最大的两个隐患**：
   - **指标口径混乱**：申请书里 TTTS_SAM 报 **Dice 0.82**，TTTSNet 报 **mIoU 0.64**，两者不是一个量纲，放在一起会让评审/读者误判。
   - **申请书愿景的后三环（图谱/配准/交通支）在代码里完全不存在**，只是设计示意图。基金可以写"拟研究"，但要清楚这是从零开始，不是"已有基础"。

5. **短期该做的不是继续加模型模块，而是收敛**：把 ViT anchor + SFY 外部验证 + 失败模式分析做扎实，回应"是不是只靠 18 倍参数量"的质疑，然后动笔写论文。文档 `11_paper_direction_guidance.md` 的判断是对的，本文档在它基础上补充可执行细节。

## 1. 申请书愿景 vs 当前资产：差距地图

申请书把技术路线分成五层。逐层对照代码现状：

| 层 | 申请书描述 | 代码/实验现状 | 差距 |
|---|---|---|---|
| **数据层** | FetReg2021 + 院内视频；伦理脱敏、病例级划分、质量分层（清晰/轻度/重度/不可判读）、分层标注规范 | 有 FetReg2021（2060 训练/658 测试）+ SFY 94 帧（单视频）。**无质量分层实现，无病例级划分脚本，无中心线/分叉点/交通支标注** | 大。质量分层、标注规范目前是纸面设计 |
| **分割层** | SAM ViT-B 任务后训练；边界+边缘+clDice+骨架一致性+连通组件约束；输出 mask/概率图/骨架/端点/分叉/低可信区域 | TTTSNet(CNN) + 可选 SAM ViT-B backbone；已有 Dice+BCE+CE，**clDice 已实现**（`SoftCLDiceLoss`）；边界/边缘 loss 在 TTTS_SAM 有、TTTSNet 里没接。**无骨架/端点/分叉/连通组件输出，无低可信区域** | 中。分割主干成立，但"拓扑感知"目前只有 clDice 一项，且收益微弱 |
| **提示层** | 自动提示（中心线采样正负点、候选框）、候选 mask 筛选、低可信提示 | **在 TTTS_SAM 项目里做过**（APG 0.70、centerline 0.83）。**TTTSNet 仓库里没有提示机制**（TTTSNet 是免提示 CNN） | 中。资产在另一个仓库，需要迁移/引用 |
| **无标注层** | 质量分层、伪标签、跨帧一致性、边缘感知 MAE | 伪标签半监督（**失败**）、时序一致性（**失败**）；MAE 在 UDP_PERSAM（**negative result**） | 已探索，基本都是负结果。申请书已诚实降级为"辅助+闭环验证"，方向正确 |
| **图谱层** | mask→血管图 G=(V,E)→短窗口配准→局部图谱→交通支候选→专家确认 | **完全没有代码**。申请书里图4/5/6 均标注"示意，不代表当前已实现" | 最大。这是三年计划里全新的工作 |

**结论**：当前项目 = 申请书"分割层"的一个子集，且技术路线（TTTSNet CNN）和申请书主线（SAM 提示驱动）部分脱节。ViT backbone 实验是二者的桥，但它只用了 SAM 的 image encoder，没用 prompt encoder / mask decoder，**不是申请书说的"基础模型任务后训练"范式**。

## 2. 实验证据链复盘：哪些能用、哪些是坑

### 2.1 可信、可直接写进论文/基金的结论

| 结论 | 证据 | 强度 |
|---|---|---|
| **预训练 ViT backbone 稳定优于 CNN baseline** | 3 seeds：ViT 0.6389±0.0025 vs CNN ~0.603；SFY 上 ViT 0.6524 也更高 | 强（多 seed + 跨域一致） |
| **ViT 优势能跨域迁移到 SFY** | SFY mIoU 0.6524、clDice 0.837，未崩溃 | 中强（但 SFY n=94 单视频） |
| **损失函数形式不是瓶颈** | AUFL 30ep 0.5647 < baseline 30ep 0.5720 | 中（仅 30ep，方向性可靠） |
| **时序一致性 loss 在单帧 mIoU 下无收益** | v1 0.549 / v2 0.546 / v3 0.604，均 ≤ baseline；no-loss 消融 0.554 | 强（多配置一致），可作系统负结果 |
| **朴素半监督（宽松伪标签）无收益** | Semi v2 0.5955 < baseline 0.605 | 中，可作负结果 |
| **弱提示对 SAM 足够（centerline≈GT 提示）** | TTTS_SAM：centerline 0.829 vs GT 0.820 | 强，但属于 TTTS_SAM 仓库资产 |
| **无提示随机点不足以发挥 SAM** | fully-random 0.575 vs GT-mask 采样 0.679 | 强，negative result |

### 2.2 必须小心的坑

1. **`custom_augmentations.py` 概率 bug（已修复）**：修复前**所有** baseline/ViT/Temporal/Semi 实验都没真正启用激光/灰尘/光纤/结构缺陷增强。
   - EXPERIMENTS.md 里的 EXP-001~017 是**修复后重训**的（时间戳 2026-06-23 之后），这些可用。
   - `09` 文档里 0.5992、0.6191 这些旧数字是**修复前**的，**不要和新数字混用**。论文/基金只用修复后的一套。

2. **"TTTS_SAM A0.2.5 random points 0.679" 不是无提示结果**：它是从 **GT mask** 采样 10 前景+10 背景点，属于**点监督上界**。文档 `08` 已澄清。任何地方引用这个数字都必须写清楚"GT 点监督上界"，否则是学术表述错误。

3. **指标量纲混用（最高优先级）**：
   - TTTS_SAM 阶段报 **Dice**（0.82 / 0.70 跨域）。
   - TTTSNet 阶段报 **mIoU**（0.64）+ Dice（0.76）。
   - 申请书"研究基础"里同时出现 0.82 和 0.64，读者会以为性能下降了。实际上 TTTSNet 的 Dice 0.76 和 TTTS_SAM 的 Dice 0.82 才是可比的，且两者数据/设置不同。**必须在申请书和论文里统一：要么全用 Dice，要么 mIoU 和 Dice 成对出现，并注明数据集和提示设置。**

4. **ViT 参数量质疑（94.92M vs 5.31M，约 18×）**：目前**没有**做 frozen encoder / LoRA / adapter 的参数高效消融。这是论文一定会被问的问题，也是基金"基础模型适配"创新点的软肋。

5. **SFY 统计力**：94 帧、单视频、polygon 粗标注。直接比 mIoU 会偏低。必须 bootstrap CI + per-image paired test + 用 surface_dice 缓解边界惩罚，且诚实写成 "external pilot / real-world validation subset"。

### 2.3 数字对照表（修复后，来自实验目录 summary.json）

| 模型 | 内部 Val mIoU | 内部 Val Dice | SFY mIoU | SFY Dice | SFY clDice | 参数量 | 延迟 |
|---|---|---|---|---|---|---|---|
| CNN baseline (v1.0.0, 3 seeds) | ~0.603 | ~0.737 | 0.6275 (seed42) | 0.7495 | 0.808 | 5.31M | 12.1ms |
| **ViT+Layerwise LR (v2.1.0, 3 seeds)** | **0.6389±0.0025** | **0.7652±0.0024** | **0.6524±0.0080** | **0.7723±0.0062** | 0.837 | 94.92M | 17.9ms |
| ViT+Transformer+Layerwise (v4.1.0) | 0.6409 | 0.7669 | 0.6433 | 0.7614 | 0.832 | 95.19M | 18.5ms |
| ViT+Layerwise+clDice fixed (v2.2.0) | 0.6417 | 0.7683 | 0.6512 | 0.7673 | 0.841 | 94.92M | 17.9ms |
| Temporal v3 (v1.3.0) | 0.6038 | 0.7377 | 0.5982 | 0.7271 | 0.788 | 5.31M | 6.4ms |

> 注：clDice fixed（v2.2.0）在拓扑指标（clDice 0.841、SFY clDice）上略优于纯 ViT，可作为"拓扑感知有效"的**小而真实**的证据点，但它不是全面超越主模型，定位应为**拓扑消融**而非主结果。

## 3. 代码与工程现状评估

**优点**：
- 实验管理规范成熟（`EXPERIMENT_LAYOUT.md` 版本号体系、EXP 编号、summary.json、软链接），可复现性好。
- 分层学习率、clDice、多模型（CNN/ViT/Transformer decoder）已在统一 `tools/train.py` 里支持，配置化程度高。
- 有跨域评测（SFY）、效率统计（参数量/延迟）脚本产物。

**技术债 / 风险（来自 README "已知漏洞" + 代码阅读）**：
1. **训练入口重复**：`train.py` / `train_temporal.py` / `train_semi.py` / `train_sam_random.py` 大量重复（loss/优化器/可视化/checkpoint）。改一处要改四处，容易引入不一致。
2. **路径硬编码**：configs 里 `train_paths/val_paths`、`sam_checkpoint`、伪标签 `--unlabeled_path` 全是服务器绝对路径。换机器必崩，也不利于开源（MIA 要求 open access 仓库）。
3. **时序 loss 实现很薄**：`temporal_loss.py` 只有一阶 L1 概率图一致性 + 置信度加权，没有运动补偿/特征级/teacher 加权。申请书说的"运动补偿后跨帧一致"目前没实现——所以"时序无效"的结论要谨慎表述为"**在当前朴素实现下**无效"。
4. **拓扑输出缺失**：申请书要 mask/概率图/骨架/端点/分叉/连通组件/低可信区域，代码只输出 mask + 概率。骨架/分叉/连通组件**指标都还没算过**（只有 clDice、surface_dice）。
5. **两个仓库割裂**：TTTS_SAM（提示、APG、centerline、边界 loss）和 TTTSNet（当前主仓）是分开的。申请书把两者当成一个连续故事，但代码没打通。

## 5. 行动指南

分两条线：**论文线（未来 2–4 周，投稿导向）** 和 **基金线（三年愿景对齐）**。

### 5.1 论文线（优先，直接决定能不能投 MIA）

主问题按 `11` 文档收敛为：**低资源 TTTS 胎儿镜血管分割中，预训练视觉表征的跨域泛化与临床可用性系统评估**。不要再以"提新模块"为主线。

**第 1 优先（回应必答质疑）**：
- [ ] **统一指标口径**：全项目核对，主表用 mIoU+Dice+clDice+surface_dice 四件套，成对出现，注明数据集/提示。
- [ ] **参数高效消融**（回应 R2）：在 ViT anchor 上做三档——① frozen encoder 只训 decoder；② 当前 layerwise LR；③ full finetune。再加一个 LoRA/adapter quick run。报告 trainable params。
- [ ] **加一个同量级公开 baseline**：SegFormer-B0/B1 或 DeepLabV3+，证明不是"任意大模型都行"，而是 SAM 预训练表征有价值。

**第 2 优先（做实证据链）**：
- [ ] baseline 与 ViT anchor 的 **per-image paired test + bootstrap CI**（内部 Val 和 SFY 都做）。
- [ ] **失败模式分类**（failure mode taxonomy）：细血管断裂、低对比、激光反光、器械遮挡各挑 2–3 例，做 baseline vs ViT 定性对比图。
- [ ] **补拓扑结构指标**：至少加骨架召回 / 连通组件错误数（clDice 已有），支撑"拓扑感知"叙事，也直接对齐基金考核指标。

**第 3 优先（数据资产增值）**：
- [ ] 对 SFY 94 帧做最小手工分层（高反光/器械/细血管稀疏密集），做 subgroup 分析。

**明确不做**（防发散，来自 `11` 的 7 问规则）：更深的 Transformer decoder、更复杂 temporal block、随机组合模块、无假设的新 loss。

### 5.2 基金线（三年愿景如何对齐现有资产）

基金评审看的是"临床价值 + 可行性 + 前期基础"。现有资产足以支撑**第一年**（分割主线），但要诚实标注后两年是新工作。

**建议的对齐写法**：
1. **第一年（分割主线）= 现有资产**：直接用 TTTSNet/ViT + FetReg + SFY 的三 seed 结果 + 跨域验证 + 拓扑指标，作为"已建立稳定基线"的证据。这块最扎实。
2. **把 TTTS_SAM 的提示资产接回来**：APG(0.70)、centerline(0.83)、边界/边缘 loss 是申请书"提示层"和"拓扑约束"的直接前期基础。建议在申请书"研究基础"里把 TTTS_SAM 和 TTTSNet 讲成一条线时，**明确两者的技术差异**（SAM 提示驱动 vs TTTSNet 免提示 CNN），否则评审会发现 backbone 实验并不等于 SAM 适配。
3. **MAE 负结果**：保持现在的诚实写法（辅助+闭环验证），这是严谨性加分项，不要包装成成功。
4. **后两年（图谱/配准/交通支）**：用示意图，动词一律用"拟""将",配套风险应对（申请书第五节风险分析已写得不错，保留）。补一句"在第一年分割主线稳定后启动"，体现渐进式可行性。

**基金里需要立刻修的具体点**：
- [ ] R1 指标口径：申请书"研究基础"章节把 0.82(Dice) 和 0.64(mIoU) 的量纲、数据集、提示条件逐一标注清楚。
- [ ] R3：确认所有"图谱/配准/交通支"描述都带"拟/将/示意"，不出现"已实现/已构建"。
- [ ] 前期工作量数字（150+ 实验、2200+ GPU 小时）与实验记录能对上——目前 EXPERIMENTS.md 只列了 17 个 EXP + 附录废弃实验，TTTS_SAM/UDP_PERSAM 的实验记录在另外的仓库，建议保留可追溯清单以备答辩。

### 8.0 第一步永远是"盘点"，不是"标注"

在动任何标注之前，先花半天做一张**数据台账**。无从下手往往是因为没先看清家底。

- [ ] 统计：视频数、总时长、总帧数、来源病例数（**病例数比帧数重要**）、设备型号、分辨率、帧率。
- [ ] 记录每个视频的元信息：病例 ID（脱敏后编号）、Quintero 分期（若有）、是否含激光凝固操作、是否含器械、羊水清亮度主观评级。
- [ ] 产出一张 `data_inventory.csv`（一行一个视频/片段），字段见下方 8.2/8.3。
- [ ] **【决策】** 明确"一个样本"的单位：单帧？短片段（连续 N 帧）？这决定后续划分和时序实验能不能做。

### 8.1 合规与脱敏（先过这关，否则后面全是白工）

- [ ] 确认伦理批件编号、病例纳入时间范围、数据使用范围（申请书里现在是待补，落地时必须有）。
- [ ] 去标识化：去除病历号/姓名/日期水印/设备叠加的患者信息；文件名用脱敏编号替换。
- [ ] 建立"原始数据"与"研究数据"的物理隔离目录，研究流程只接触脱敏副本。
- [ ] 记录数据访问权限清单（谁能碰、放在哪、备份在哪）。
- [ ] **成果展示只用脱敏帧**——论文/基金配图前先过一遍这条。

### 8.2 病例级划分（防数据泄漏，这是评审最爱挑的点）

- [ ] **按病例/视频划分 train/val/test，绝不让同一台手术的连续帧跨集**（否则 mIoU 虚高，一票否决级问题）。
- [ ] 划分时记录每个 split 的：病例数、帧数、前景占比分布、质量等级分布，确认分布不失衡。
- [ ] 固定划分并存成 `data_split.json`（可复现）。
- [ ] **【决策】** 院内数据是做**独立测试集**（推荐，最能证明跨域泛化），还是也进训练集？建议：院内先全部留作 test/external validation，FetReg 继续做训练，先把"跨域下降幅度"这个故事讲透。

### 8.3 质量分层（申请书考核指标之一，且直接影响结论可信度）

按申请书定义落地四级：**清晰 / 轻度退化 / 重度退化 / 不可判读**。

- [ ] 定义可操作的分级标准（不要只靠主观）：给每帧打亮度、对比度、反光比例、模糊程度、遮挡面积、血管可见性、器械干扰几个维度的分数，再映射到四级。
- [ ] 先人工标 100–200 帧作为分级"金标准"，再考虑用简单规则/小模型自动分级其余帧。
- [ ] 产出 `quality_labels.csv`（帧 → 等级 + 各维度分数）。
- [ ] 评测时**按质量等级分别报指标**，避免平均值掩盖重度退化帧上的失效——这正是论文能讲出别人讲不出的东西。
- [ ] "不可判读"帧不作为强制分割目标，留作**拒识/低可信提示**的评测样本。

### 8.4 关键帧筛选（视频→可标注帧，控制标注成本）

- [ ] 从连续视频里抽关键帧：固定间隔（如每 N 帧）+ 去除高度冗余帧（相邻相似度过高的去重）+ 剔除"不可判读"帧。
- [ ] 保留帧的时间戳/帧号/来源视频，为后续时序、短窗口配准留元信息（即使现在不做）。
- [ ] **【决策】** 首批标注预算多少帧？建议先定一个能出论文的量级（如 300–500 帧覆盖尽量多病例），而不是一次标全部。

### 8.5 分层标注体系（决定你能讲多大的故事）

按申请书三层推进，**从便宜到贵、从主线到探索**：

- [ ] **第一层 · 血管像素 mask**（必做，最便宜）：统一标注规范——血管边界、遮挡处、高光处、血管交叉处怎么处理，写成一页 `annotation_spec.md`。
- [ ] **第二层 · 结构标注**（推荐，是你的差异化）：中心线、端点、分叉点、低可信区域。**这层是"拓扑感知"论文和基金提示层的关键**，即使只标一个小子集（如 50–100 帧）也够撑起 clDice/骨架召回/分叉召回的评测。
- [ ] **第三层 · 临床语义标注**（后置，最贵）：血管赤道、疑似交通支、A-A/A-V/V-V 类型、专家置信度。**早期不铺开**，等模型能生成候选后再让专家确认（申请书的"高召回候选→专家确认"策略是对的）。
- [ ] **【决策】** 中心线/分叉点是从 mask 自动骨架化 + 人工修正，还是纯人工标？建议前者（半自动）以省成本。

### 8.6 标注质控（一致性决定数据能不能发表）

- [ ] 版本管理：标注文件进 git 或专门的版本目录，每次修订留记录。
- [ ] 抽样复核：随机抽 10–20% 由第二位标注者/专家复核，计算标注者间一致性（如 Dice/IoU agreement）。
- [ ] 对边界模糊、高光遮挡、器械覆盖、血管交叉四类困难情况，统一处理原则并写进 `annotation_spec.md`。
- [ ] 记录"不确定/不可判读"标签，别强行二分——这本身就是低可信提示的训练/评测信号。

### 8.7 评测协议冻结（一次定好，后面所有实验共用）

- [ ] 主指标：mIoU + Dice；结构指标：clDice + 骨架召回 + 分叉召回 + 连通组件错误 + surface_dice；边界：HD95/ASSD（可选）。
- [ ] 统一预处理：院内帧 resize 策略、mask 二值化阈值（255→1）、评测时是否 resize 回原图对齐 GT。
- [ ] 统一报告方式：**FetReg val → 院内 external 的相对下降幅度**，而不是只看绝对值（缓解粗标注/域差异带来的不公平）。
- [ ] 小样本处理：bootstrap CI + per-image paired test，别只报单点数字。
- [ ] 把协议写成 `eval_protocol.md`，冻结后不再改，保证所有模型可比。

### 8.8 数据工程与可复现（顺手做，省未来的命）

- [ ] 统一目录结构：`images/ masks/ centerlines/ quality_labels.csv data_split.json data_inventory.csv annotation_spec.md eval_protocol.md`。
- [ ] 消除代码里的绝对路径（对应本文档 R6），数据根目录用环境变量/CLI 传入——**开源仓库（MIA open access）必须做**。
- [ ] 写一份 `DATASET.md`：来源、规模、脱敏说明、划分、质量分层、标注规范、局限（诚实写单中心/样本量）。

### 8.9 优先级与产出物对照

| 阶段 | 动作 | 产出物 | 服务于 |
|---|---|---|---|
| P0 | 盘点 + 合规脱敏 | `data_inventory.csv`、脱敏数据 | 一切的前提 |
| P1 | 病例级划分 + 质量分层 | `data_split.json`、`quality_labels.csv` | 基金考核指标①②、跨域故事 |
| P2 | 第一层 mask 标注 + 质控 | mask + `annotation_spec.md` | 分割主线、外部验证 |
| P3 | 冻结评测协议 | `eval_protocol.md` + 主结果表 | 论文主表、可比性 |
| P4 | 第二层结构标注（子集） | 中心线/分叉点 | 拓扑感知论文/基金提示层（差异化） |
| P5 | 第三层临床语义（后置） | 交通支候选确认表单 | 基金后两年 |

> **落地顺序建议**：P0→P1→P2→P3 打通后，你就已经有一篇 "真实院内跨域胎儿镜血管分割 + 质量分层评测" 的论文骨架了；P4 是把它从"又一个分割论文"抬升到"拓扑感知/临床可用"的关键，也最能对齐基金；P5 留给基金后两年。**不要等全部标完才开始训练**——P2 一有量就可以先跑起来。
